This is a job-application written test (笔试) for 上海魔拾科技 (Amoros Tech), due Sunday 2026-11-08 24:00 Beijing time. Full problem statement (verbatim, Chinese):

题目：利用 AI 开发一个解决系统安全的工具
背景：对于一套运行中的系统，存在着大量安全漏洞，这些漏洞隐藏在操作系统、中间件（如 Nginx、Redis、MySQL 等）、开源框架与组件中。全世界有无数黑客在寻找这些漏洞并伺机发起攻击，与此同时，也有大量安全工作人员在作着同样的努力，发现漏洞，并公之于众，督促大家及时更新系统。
方案要求：根据已经在互联网公开发布的漏洞清单，对照一套特定的运行中的系统实际情况，定期给出更新建议，甚至辅助运维人员操作更新流程，让系统保持在相对安全的状态。
交付要求：给出设计思路与相应的设计文档，并由 AI 开发实现。需要提供与 AI 互动时涉及的所有 Prompt、Skills、第三方开源仓库链接，及所有中间产物，并给出一个可 Demo 的成品。具体开发时涉及的流程范式、开发语言、人机界面等不作限制，成品仅需要可 Demo，不必考虑过多细节。如在方案要求之外有其它补充功能，也可以一并提供。


Build the complete submission in this (empty, private) repo https://github.com/bigdu332/moshi-vuln-guard. Everything user-facing (README, design doc) should be written in Chinese.

What a good result looks like (you decide architecture/details; these are expectations, not a prescription):
1. A working tool that: (a) collects an asset inventory of a target system — OS packages (dpkg/rpm/apk), middleware versions (nginx, redis, mysql, etc.), and app dependencies (e.g. requirements.txt, package.json, pom.xml, go.mod), from the local host and ideally a remote host via SSH or a Docker container/image; (b) matches assets against public vulnerability data (e.g. OSV.dev API, NVD, CISA KEV for known-exploited prioritization, EPSS for exploit probability; reasonable to use or reference open-source tools like Trivy/Syft/Grype/osv-scanner, with links); (c) prioritizes findings (CVSS + KEV + EPSS + exposure); (d) uses an LLM to produce human-readable update recommendations and a concrete, reviewable remediation plan (commands, pre-checks, backup, rollback), with a human-approval step before any change is executed (dry-run by default); (e) runs on a schedule and produces reports (HTML/Markdown) plus a simple web UI or dashboard for the demo. The LLM should be pluggable (OpenAI-compatible API via env var) with a deterministic/template fallback so the demo works without an API key.
2. A reproducible demo: e.g. docker-compose that spins up a deliberately outdated target (old nginx/redis/mysql images, an app with old vulnerable deps) and the tool scanning it, with clear one-command instructions. Run it yourself, and commit sample output reports and screenshots of the UI as intermediate artifacts.
3. docs/: 设计思路与设计文档 (architecture diagram in mermaid, data flow, module design, prioritization logic, safety design for auto-remediation, limitations and future work).
4. ai-process/ (or similar): all prompts used with the AI during development (record this task prompt verbatim plus the key prompts you used, and the runtime LLM prompt templates), any skills/agent rules files, a list of third-party open-source repos with links, and intermediate artifacts (plans, iteration notes). Be honest that the tool was developed with Cursor AI agents.
5. Tests for core logic (version comparison, matching, prioritization), and a clean README with quick start.

Commit to a branch and open a pull request into main. In your final report give: the PR link, a short Chinese summary of architecture and features, exact demo commands, and anything that didn't work or needs the user's input (e.g. an LLM API key).
